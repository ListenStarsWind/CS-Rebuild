# 终端 ESC 转义序列与常见控制格式

在 C 字符串中：

```c
"\033"
```

其中 `\033` 是八进制转义，数值为：

```text
033₈ = 27₁₀ = 0x1B
```

ASCII 中编号 `27` 的字符是控制字符 `ESC`。

也可以写成：

```c
"\x1B"
```

因此：

```c
"\033[2K"
```

本质上是发送如下字节：

```text
ESC  [  2  K
```

终端不会把它们当作普通文本显示，而会把它识别成一个控制序列。

---

## 1. ESC 的真正作用

可以粗略理解为：

```text
ESC
 ↓
告诉终端：
“后面开始出现一个转义序列，请按控制语法解析。”
```

但需要注意：

> ESC 并不意味着后面所有字符永久进入“控制模式”。

终端只会按照当前转义序列的语法继续读取，直到遇到这个序列规定的结束位置。

例如：

```text
ESC [ 2 K
```

解析过程是：

```text
ESC
│
└─ 开始转义序列

[
│
└─ 选择 CSI 控制格式

2
│
└─ 参数

K
│
└─ 最终命令字符，同时结束该 CSI 序列
```

所以：

```c
printf("\033[2Khello");
```

实际上相当于：

```text
执行：ESC [ 2 K
然后正常输出：hello
```

---

# 2. ESC 后面的字符决定采用哪一种控制格式

常见结构大致可以看成：

```text
ESC + 控制格式标识 + 参数/内容 + 结束标识
```

其中最常见的几类是：

```text
ESC [     CSI    光标、颜色、擦除、终端状态等
ESC ]     OSC    设置窗口标题等操作系统级终端属性
ESC P     DCS    设备控制字符串
ESC _     APC    应用程序命令
ESC ^     PM     隐私消息
```

实际日常编程中，绝大多数情况都只需要认识：

```text
CSI
OSC
```

而其中最重要的又是：

```text
CSI
```

也就是：

```text
ESC [
```

---

# 3. CSI：控制序列引入器

CSI 可以理解为“控制序列语法”。

最常见写法：

```text
ESC [ 参数 命令
```

在 C 中：

```c
"\033[参数命令"
```

更完整的结构可以表示成：

```text
ESC [ 参数字节 中间字节 最终字节
```

日常使用通常只会看到：

```text
ESC [ 参数 ; 参数 ; ... 命令
```

例如：

```text
ESC [ 31 m
ESC [ 1 ; 31 m
ESC [ 2 K
ESC [ 10 ; 20 H
```

其中：

```text
[
```

表示进入 CSI。

数字：

```text
1
2
31
10
20
```

是参数。

`;`

用于分隔多个参数。

最后一个字符：

```text
m
K
H
```

是具体命令。

因此可以把 CSI 直观理解为：

```text
ESC [ 参数表 命令
```

---

# 4. CSI 参数规则

参数通常是十进制整数：

```text
ESC [ 2 K
      ↑
     参数
```

多个参数用：

```text
;
```

隔开：

```text
ESC [ 10 ; 20 H
```

即：

```text
参数1 = 10
参数2 = 20
命令 = H
```

很多命令允许省略参数。

例如：

```text
ESC [ A
```

通常相当于：

```text
ESC [ 1 A
```

即向上移动一行。

不过：

> 参数省略后的默认值由具体命令决定，并不是所有 CSI 命令都统一默认成 `1`。

---

# 5. 常见光标移动命令

## `A`：光标向上

```text
ESC [ n A
```

向上移动 `n` 行。

例如：

```c
printf("\033[3A");
```

表示：

```text
光标向上移动 3 行
```

---

## `B`：光标向下

```text
ESC [ n B
```

例如：

```text
ESC [ 2 B
```

向下移动两行。

---

## `C`：光标向右

```text
ESC [ n C
```

例如：

```text
ESC [ 5 C
```

向右移动五列。

---

## `D`：光标向左

```text
ESC [ n D
```

例如：

```text
ESC [ 4 D
```

向左移动四列。

因此：

```text
A = 上
B = 下
C = 右
D = 左
```

---

# 6. 光标绝对定位

常见命令：

```text
H
f
```

格式：

```text
ESC [ 行 ; 列 H
```

例如：

```text
ESC [ 10 ; 20 H
```

表示：

```text
把光标移动到第 10 行、第 20 列
```

C：

```c
printf("\033[10;20H");
```

其中：

```text
10 = 行
20 = 列
H  = 设置光标位置
```

通常坐标从：

```text
1,1
```

开始，而不是从 `0,0` 开始。

---

# 7. 擦除屏幕：J

格式：

```text
ESC [ n J
```

`J` 表示对显示区域进行擦除。

常见参数：

```text
0J    从光标位置擦除到屏幕末尾
1J    从屏幕开头擦除到光标位置
2J    擦除整个屏幕
3J    某些终端中连滚动缓冲区一起清除
```

例如：

```c
printf("\033[2J");
```

表示清屏。

不过：

```text
ESC [ 2 J
```

通常只是擦除屏幕内容，并不意味着光标一定回到左上角。

因此完整的“清屏并回到左上角”经常写成：

```c
printf("\033[2J\033[H");
```

---

# 8. 擦除当前行：K

这就是：

```text
ESC [ 2 K
```

所属的命令。

格式：

```text
ESC [ n K
```

`K` 表示擦除当前行的一部分或全部。

参数：

```text
0K    从当前光标位置擦除到行尾
1K    从行首擦除到当前光标位置
2K    擦除整个当前行
```

所以：

```text
ESC [ 2 K
```

可以读成：

```text
ESC     开始转义序列
[       使用 CSI
2       擦除模式 2
K       执行“行擦除”命令
```

即：

```text
清除当前整行
```

---

# 9. SGR：文字显示属性

`m` 是极其常用的 CSI 命令。

格式：

```text
ESC [ 参数 ; 参数 ; ... m
```

它用于控制：

```text
颜色
粗体
下划线
反显
背景色
其他显示属性
```

通常称为 SGR。

例如：

```c
printf("\033[31mHello\033[0m");
```

其中：

```text
ESC [ 31 m
```

设置前景色。

```text
ESC [ 0 m
```

恢复默认显示属性。

常见参数：

```text
0     重置所有显示属性

1     粗体或增强亮度
2     弱化
3     斜体
4     下划线
5     闪烁
7     前景与背景反转
8     隐藏
9     删除线
```

颜色：

```text
30    黑
31    红
32    绿
33    黄
34    蓝
35    品红
36    青
37    白
```

背景：

```text
40    黑
41    红
42    绿
43    黄
44    蓝
45    品红
46    青
47    白
```

亮色通常为：

```text
90 ~ 97     亮前景色
100 ~ 107   亮背景色
```

例如：

```text
ESC [ 1 ; 31 m
```

表示同时设置：

```text
1  → 粗体/增强
31 → 红色
m  → 应用显示属性
```

---

# 10. 256 色

现代终端通常还支持：

```text
ESC [ 38 ; 5 ; n m
```

设置前景色。

```text
ESC [ 48 ; 5 ; n m
```

设置背景色。

其中：

```text
n = 0 ~ 255
```

例如：

```c
printf("\033[38;5;208mHello\033[0m");
```

---

# 11. 真彩色

很多现代终端支持 24 位颜色：

```text
ESC [ 38 ; 2 ; R ; G ; B m
```

设置前景色。

例如：

```text
ESC [ 38 ; 2 ; 255 ; 128 ; 0 m
```

表示：

```text
R = 255
G = 128
B = 0
```

背景色则为：

```text
ESC [ 48 ; 2 ; R ; G ; B m
```

---

# 12. 滚动命令

## `S`

```text
ESC [ n S
```

屏幕内容向上滚动 `n` 行。

## `T`

```text
ESC [ n T
```

屏幕内容向下滚动 `n` 行。

可以记为：

```text
S → 向上滚动
T → 向下滚动
```

---

# 13. 保存与恢复光标

很多终端支持：

```text
ESC [ s
```

保存当前光标位置。

```text
ESC [ u
```

恢复光标位置。

例如：

```c
printf("\033[s");
printf("\033[10;20H");
printf("xxx");
printf("\033[u");
```

流程是：

```text
保存当前位置
↓
移动光标
↓
输出内容
↓
回到原位置
```

不过这一组属于广泛实现的终端功能，具体兼容性需要考虑终端实现。

---

# 14. 私有模式：?

还经常会遇到：

```text
ESC [ ? 参数 h
ESC [ ? 参数 l
```

其中：

```text
?
```

表示使用某类终端私有扩展参数。

通常：

```text
h = 设置/开启模式
l = 重置/关闭模式
```

最常见的是：

```text
ESC [ ? 25 h
```

显示光标。

```text
ESC [ ? 25 l
```

隐藏光标。

例如：

```c
printf("\033[?25l");   // 隐藏光标
printf("\033[?25h");   // 显示光标
```

这里：

```text
?25
```

代表某个具体终端模式。

```text
h
```

表示开启。

```text
l
```

表示关闭。

注意：

> 这一类很多属于历史终端及现代终端模拟器扩展，并不是所有终端实现完全一致。

---

# 15. OSC：操作系统命令

另一类常见序列是：

```text
ESC ]
```

即：

```text
OSC
```

它主要用于设置终端窗口相关属性，而不是移动光标。

典型结构：

```text
ESC ] 参数 ; 内容 结束符
```

最常见用途之一是设置终端标题。

例如：

```text
ESC ] 0 ; Hello BEL
```

其中：

```text
0       操作编号
Hello   内容
BEL     结束 OSC
```

C 中可以写：

```c
printf("\033]0;Hello\a");
```

`\a` 对应 ASCII 的：

```text
BEL
```

即响铃控制字符。

现代终端中 OSC 也经常使用：

```text
ESC \
```

作为结束符。

也就是：

```text
ESC ] ... ESC \
```

---

# 16. DCS

格式：

```text
ESC P ... ESC \
```

即：

```text
ESC P
```

启动 DCS。

DCS 主要用于比较复杂的设备控制或终端扩展通信。

一般普通 C 程序几乎不需要手写它。

可以简单记为：

```text
ESC P
↓
进入一段设备控制数据

ESC \
↓
结束
```

---

# 17. ST：字符串终止符

前面的：

```text
ESC \
```

本身也是一个控制结构，通常表示：

```text
ST
```

即结束某些字符串型控制序列。

因此：

```text
OSC
DCS
APC
PM
```

这一类控制格式经常具有类似结构：

```text
ESC 某字符
    ↓
开始控制字符串

...

ESC \
 ↓
结束控制字符串
```

---

# 18. ESC 本身也可以直接形成短控制序列

并不是所有 ESC 控制都必须经过：

```text
[
```

例如一些传统终端指令直接采用：

```text
ESC + 一个字符
```

因此：

```text
ESC [
```

只是 ESC 控制体系中的一种格式。

更准确地说：

```text
ESC
│
├─ [
│   └─ CSI
│
├─ ]
│   └─ OSC
│
├─ P
│   └─ DCS
│
├─ _
│   └─ APC
│
├─ ^
│   └─ PM
│
└─ 其他字符
    └─ 某些传统 ESC 控制命令
```

# 19. 最常见 CSI 命令速查

```text
命令        含义

nA          光标向上 n 行
nB          光标向下 n 行
nC          光标向右 n 列
nD          光标向左 n 列

nE          光标向下 n 行并移动到行首
nF          光标向上 n 行并移动到行首
nG          移动到当前行第 n 列

r;cH        移动到第 r 行、第 c 列
r;cf        同类光标定位

nJ          擦除显示区域

nS          向上滚动
nT          向下滚动

...m        设置文字显示属性

s           保存光标位置
u           恢复光标位置
```

其中真正应该重点记忆的其实只有：

```text
A B C D      光标移动
H            光标定位
J            擦屏幕
K            擦行
m            文字颜色/属性
```

# 20. 一个完整解析例子

例如：

```c
printf("\033[1;31mERROR\033[0m");
```

逐字节来看：

```text
ESC
[
1
;
3
1
m
E
R
R
O
R
ESC
[
0
m
```

终端首先看到：

```text
ESC [
```

于是知道：

```text
开始 CSI
```

随后读取：

```text
1;31
```

作为参数。

看到：

```text
m
```

以后确定：

```text
CSI 序列结束
执行 SGR 命令
参数 = 1,31
```

于是：

```text
1  → 加粗/增强
31 → 红色
```

随后：

```text
ERROR
```

因为已经离开 CSI 序列，所以按照普通字符显示。

之后：

```text
ESC [ 0 m
```

再次进入 CSI：

```text
0 → 重置显示属性
m → SGR
```

最终恢复正常显示。

---

# 21. `\033[2K` 的最终理解

因此：

```c
"\033[2K"
```

不应该简单理解成：

```text
\033：后面是控制内容
[   ：某种特殊符号
2K  ：命令
```

更准确的理解是：

```text
\033
│
└─ ASCII ESC，开始一个转义序列

[
│
└─ 指定该序列采用 CSI 格式

2
│
└─ CSI 参数，表示擦除模式 2

K
│
└─ CSI 最终命令字符：
   执行行擦除，同时结束这个 CSI 序列
```

即：

```text
ESC [ 2 K
```

可以抽象为：

```text
控制序列引入
    ↓
选择控制语法
    ↓
参数
    ↓
命令
```

# 22. 标准与兼容性

这套体系来源于终端控制标准以及历史上的字符终端体系。

现代常见终端：

```text
Linux 终端
SSH 终端
xterm 类终端
Windows Terminal
VS Code 集成终端
```

通常都支持大量这种控制序列。

因此它具有很强的平台适应性，但不能认为所有序列在所有终端上都绝对一致。

尤其是：

```text
颜色扩展
256 色
真彩色
私有模式
备用屏幕
标题控制
鼠标控制
```

这些功能可能存在终端实现差异。

所以可以把它理解为：

> 一套历史悠久、被现代终端广泛继承的“终端控制协议”。

它不像自然语言，因为终端实际处理的是一串非常紧凑的字节协议。

---

# 23. 整体抽象

最终可以把终端输出理解为两类数据混合在同一个字节流中：

```text
普通字符
+
控制序列
```

例如程序发送：

```text
Hello ESC [ 31 m World ESC [ 0 m !
```

终端解析为：

```text
Hello
↓
普通文本

ESC [ 31 m
↓
将文字设为红色

World
↓
普通文本，以红色显示

ESC [ 0 m
↓
恢复显示属性

!
↓
普通文本
```

因此，终端并不是单纯地：

```text
收到字符 → 画出字符
```

而更准确地说是：

```text
收到字节流
   ↓
解析
   ↓
普通字符 ─────────→ 显示
   ↓
控制序列 ─────────→ 修改终端状态
```

也正因为如此，使用普通的：

```c
printf()
```

就能够完成：

```text
移动光标
清屏
修改颜色
擦除文字
隐藏光标
设置窗口标题
```

因为 `printf()` 本身并不知道什么是“红色”或者“清屏”。

它仅仅负责：

```text
向终端写入字节
```

真正解释：

```text
ESC [ 31 m
ESC [ 2 K
ESC [ H
```

这些协议并执行对应动作的是终端模拟器。
