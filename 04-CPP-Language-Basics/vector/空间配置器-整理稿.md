# 空间配置器

同一台电脑上，浏览器可以播放视频，编辑器也可以同时响应输入。两个程序都要用到处理器和内存。那谁来决定什么时候让哪个程序运行，又怎样给各个程序安排内存？

这些工作由操作系统协调。浏览器和编辑器各自处理视频播放和文本编辑，需要系统提供服务时，就通过操作系统的接口提出请求。操作系统内部也有分工。调度器决定接下来运行哪个任务，内存管理负责维护各个进程的地址空间，并分配和回收内存。多个应用可以共用这些机制。

把相关的工作集中起来，让上层通过约定好的接口使用下层提供的能力，这就是**分层设计**。调度相关的决策集中在调度器里，体现的是高内聚。操作系统可以调整调度算法，应用程序仍能按原来的方式使用系统服务，体现的是低耦合。

回到容器设计，也可以先问一个类似的问题。哪些决策需要容器自己做，哪些工作可以交给另一层？以动态数组为例，容器知道当前有多少个元素、什么时候需要扩容，也知道哪些对象需要迁移。等它确定需要一块多大的空间之后，从哪里取得这块空间、怎样满足对齐要求、用完后怎样归还，就可以交给专门负责存储分配的一层。负责这组工作的对象，就是空间配置器（`allocator`）。

容器可以更换空间配置器，接下来就要考虑它怎么使用不同配置器的接口。比如，有的配置器会声明自己的指针类型 `pointer`，有的会省略它。如果每个容器都自己处理这种差异，同样的规则就要在各个容器里写一遍。

适配器的作用，就是把已有的接口整理成调用方需要的形式。比如，队列适配器借助底层容器存放元素，对外提供入队和出队操作。这里要衔接的是容器和空间配置器，因此用到的是**空间配置器适配器（`allocator_traits`）**。它向容器提供统一的类型和操作。以 `pointer` 为例，配置器自己声明了，适配器就采用它。配置器省略了这个类型，适配器就根据元素类型补出默认指针类型。

接下来从空间配置器写起，先看 `wind::allocator<T>` 怎样为指定数量的元素申请存储空间，以及怎样归还这块空间。

## 1. 实现空间配置器

先搭出 `wind::allocator<T>` 的基本框架。模板参数 `T` 决定配置器为哪一种元素准备空间。我们先列出接口里用到的几个类型，以及申请、释放这两个基本操作。

```cpp
#pragma once

#include <concepts>
#include <cstddef>

namespace wind {

template <class T>
class allocator {
public:
    using value_type = T;                    // 元素类型
    using difference_type = std::ptrdiff_t;  // 元素位置差值类型
    using size_type = std::size_t;            // 元素计数类型
    using pointer = value_type*;
    using const_pointer = const value_type*;

    allocator() noexcept = default;

    template <class U>
        requires (!std::same_as<T, U>)
    allocator(const allocator<U>&) noexcept {}

    [[nodiscard]]
    T* allocate(size_type n);

    void deallocate(T* p, [[maybe_unused]] size_type n) noexcept;
};

}  // namespace wind
```

### 1.1 公开类型

`value_type` 表示配置器所管理的元素类型，在这里就是模板参数 `T`。这是配置器必须公开的类型。这里列出的 `difference_type` 和 `size_type` 则可以省略，适配器会按各自的默认规则补齐。`pointer` 和 `const_pointer` 也可以由适配器补齐。这里先显式写出它们，后面构造和销毁对象时，可以用 `pointer` 表示对象所在的位置。

`difference_type` 描述两个元素位置之间的相对关系。在同一个 `int` 数组里，用指向第 4 个元素的指针减去指向第 1 个元素的指针，结果是 `3`，表示向后相隔 3 个元素位置。交换两个指针，结果就是 `-3`。单位是元素，有符号的 `std::ptrdiff_t` 可以同时表示距离和方向。

`size_type` 同样以元素为单位，用来计数。比如，`allocate(4)` 表示为 4 个 `T` 准备存储空间。换算成字节时才计算 `4 * sizeof(T)`。差值可以有正负，计数从零开始，因此可以用差值类型对应的无符号类型来表示数量。这里明确选择了 `std::size_t`。等写到适配器，配置器省略 `size_type` 时，我们会先确定 `difference_type`，再用它对应的无符号类型补出 `size_type`。

**公开类型也是类接口的一部分。** 对于 `allocator<int>`，编译器在编译时就能确定 `allocator<int>::value_type` 是 `int`。通过类名就能取得这个类型别名，无须创建对象或读取变量的值。调用方可以用这些名字声明参数和返回类型，也可以在编译时根据配置器公开了哪些类型来选择实现。适配器接下来就会用到这一点。

### 1.2 容器需要哪些支持

**申请和释放存储空间。** 容器决定要为多少个元素留出位置，配置器根据元素的大小和对齐要求取得空间。空间用完后，再按对应的分配方式归还。

**在存储空间里构造和销毁对象。** 动态数组可以先预留 8 个位置，实际只在其中 3 个位置构造对象。移除元素时，可以先销毁对象，把腾出的位置留给后续插入。容器决定何时、在哪些位置执行这些操作，配置器可以提供相应的操作，适配器也可以补齐缺省实现。

**为容器转交内容提供判断依据。** 一个容器把内容交给另一个容器时，有时可以直接交出原来的存储空间，有时需要逐个迁移元素。如果接收方继续使用自己的配置器，能否直接接管原有空间，要看它能否在以后释放这块空间。配置器及其适配器提供这类信息，容器据此决定怎样完成转交。

### 1.3 默认构造与跨类型构造

本例用全局的 `::operator new` 和 `::operator delete` 管理存储空间，每个配置器对象都无须持有独立的内存资源。默认构造没有额外的初始化工作，交给编译器生成即可。

另一个构造函数以 `allocator<U>` 为参数，用已有的配置器对象构造 `allocator<T>` 对象。为什么需要跨元素类型构造？以双向链表为例，容器对外管理的是 `T`，实际要分配的是链表节点。一个节点除了保存 `T`，还要保存前驱、后继指针。因此，容器要能用原来管理 `T` 的配置器构造一个管理节点的配置器。这种构造能力是 C++ 对配置器的要求之一。

如果原配置器关联一个内存池，节点配置器也需要按照配置器自己的规则接续这份资源状态。容器只需把已有对象交给构造函数，资源状态怎样传递，由配置器实现。这里的 `wind::allocator<T>` 无须保存资源状态，所以跨类型构造函数的函数体为空。约束 `!std::same_as<T, U>` 则把这个构造函数限定在跨类型的场景，同类型的拷贝使用类的拷贝构造函数。

> **旁注**
>
> 跨类型构造函数的函数体即使为空，也需要显式定义。`= default` 请求编译器按语言规定生成实现，例如生成默认构造或拷贝构造。跨类型构造属于由类设计者定义的转换，编译器没有相应的默认构造规则。把这个构造函数写成普通的非模板版本，同样需要提供定义。

### 1.4 申请与释放存储空间

先从最直接的实现看起。调用方以元素数量发出请求，配置器把它换算成字节交给全局分配函数。取得的地址转换为 `T*`，容器就可以用元素位置来表示这块存储空间。

```cpp
[[nodiscard]]
T* allocate(size_type n) {
    return static_cast<T*>(::operator new(n * sizeof(T)));
}

void deallocate(T* p, [[maybe_unused]] size_type n) noexcept {
    ::operator delete(p);
}
```

释放时，调用方传回先前取得的指针以及分配时的元素数量。这里选用的无尺寸释放函数只需要地址。其他分配策略可以使用 `n`，例如按原申请的块大小归还空间。

> **旁注**
>
> `[[nodiscard]]` 表示返回值值得保留。申请成功后，如果丢弃返回的指针，调用方就失去了归还这块空间所需的地址。直接丢弃返回值时，编译器通常会给出警告。
>
> `[[maybe_unused]]` 表明参数可以有意留在接口里，即使当前函数体没有使用它。这里也可以用 `(void)n;` 显式表示有意忽略。

### 1.5 检查元素数量与对齐要求

上面的实现把 `n * sizeof(T)` 直接交给分配函数。要是乘积超出字节计数类型的范围，传给分配函数的大小就会失真。因此应先用字节数的上限除以 `sizeof(T)`，得到换算时可接受的最大元素数量，再比较请求的 `n`。

假设字节计数最多能表示 255，每个元素占 4 字节。最多能完整装下 `255 / 4 == 63` 个元素。请求 64 个时，光是要表示的 256 字节就已经超出了范围。这也是为什么检查要放在乘法前面。我们手里还有原始的 `n`，可以直接判断它会不会越界。

代码用 `byte_size_type` 表示字节数，用 `size_type` 表示元素数。这两个别名在本例中都指向 `std::size_t`，分别标明了计算两端的单位。把字节上限除以元素大小，得到的 `max_element_count` 就能与 `n` 直接比较。配置器也通过 `max_size()` 提供这个上限。请求在范围内意味着字节数可以表示，分配能否成功还取决于可用资源。

![元素数量上限的计算](https://img.mdwind.online/img/20261111132602177.png)

![元素数量上限与公开查询接口](https://img.mdwind.online/img/20261112203345019.png)

到这一步只确定了需要多少字节，起始地址还得满足另一项要求。假设某个类型要求按 64 字节对齐，即使已经拿到足够多的字节，也得从满足 64 字节对齐的地址开始放对象。`alignof(T)` 得到类型所需的对齐值，`__STDCPP_DEFAULT_NEW_ALIGNMENT__` 表示普通全局 `operator new` 提供的默认对齐。需要更大的对齐值时，分配和释放都使用带 `std::align_val_t` 的重载，并传入相同的对齐值。

```cpp
[[nodiscard]]
T* allocate(size_type n) {
    if (n > max_element_count) {
        throw std::bad_array_new_length{};
    }

    const byte_size_type bytes = n * sizeof(T);

    if constexpr (alignof(T) > __STDCPP_DEFAULT_NEW_ALIGNMENT__) {
        return static_cast<T*>(::operator new(bytes, std::align_val_t{alignof(T)}));
    } else {
        return static_cast<T*>(::operator new(bytes));
    }
}

void deallocate(T* p, [[maybe_unused]] size_type n) noexcept {
    if constexpr (alignof(T) > __STDCPP_DEFAULT_NEW_ALIGNMENT__) {
        ::operator delete(p, std::align_val_t{alignof(T)});
    } else {
        ::operator delete(p);
    }
}
```

> **旁注**
>
> 可以把这两个判断放在一起看。`n` 来自函数参数，同一个 `allocator<int>` 可以先收到请求 4，再收到请求 100，所以普通 `if` 要在每次调用时判断。对齐条件里用的却是 `alignof(T)`。编译器实例化 `allocator<int>::allocate` 时，`T` 已经确定，条件的真假也就确定了。
>
> `if constexpr` 要求条件能在编译时求值。在模板实例化时，编译器根据它选择分支，另一条分支不为这次实例化生成代码。这里的两条分支各自调用一组不同的分配和释放函数。后面写适配器时，还会用同一个机制根据某个调用表达式是否成立来选分支。

> **旁注**
>
> 随机存取存储器（RAM）中的「随机」，指的是可以按地址访问指定位置。硬件各层有自己的访问和传输粒度。例如，CPU 可以请求读取一个整数，缓存未命中时，缓存系统通常会把包含该地址的整个缓存行从下一级加载进来。程序经常会接着访问附近的数据，这样加载能利用空间局部性。
>
> 设想某个硬件访问边界每隔 8 字节出现一次。一个 4 字节整数从 `0x1004` 开始时，占据 `0x1004` 到 `0x1007`，落在同一个区域里。从 `0x1006` 开始时，则占据 `0x1006` 到 `0x1009`，跨过了区域边界。处理器可能需要从两个区域取数，再组合起来，具体代价取决于硬件。
>
> C++ 中的类型对齐约束的是对象起始地址。例如，要求按 8 字节对齐的对象，其起始地址要落在 8 字节的边界上。缓存行大小是硬件的传输粒度，类型的对齐值是对象地址须满足的约束。一个对齐合格的对象仍可能跨越缓存行。

### 1.6 在存储空间里构造与销毁对象

申请到足够容纳 8 个元素的存储空间后，容器可以先在其中构造 3 个对象。要往末尾插入第 4 个元素时，容器已经知道哪个位置空着，也知道用什么参数构造对象，只需要把这个位置和参数交给配置器。删除这个元素时，销毁操作结束对象的生命周期，容器可以把空出来的位置留给下次插入。等整块空间用完，才调用释放操作。

```cpp
template <class... Args>
void construct(pointer p, Args&&... args) {
    std::construct_at(p, std::forward<Args>(args)...);
}

void destroy(pointer p) {
    std::destroy_at(p);
}
```

这里用 `std::construct_at` 在 `p` 指定的地址构造对象。容器传来的参数可能是已有对象，也可能是临时值，`std::forward` 把这层区别传给实际调用的构造函数。`std::destroy_at` 则在同一个地址销毁已经构造好的对象。

### 1.7 配置器实例的相等比较

容器有时需要知道，能否让一个配置器实例释放另一个实例取得的存储空间。如果两个配置器分别使用独立的内存池，从池 A 取得的空间就应该归还给池 A。相等比较向容器表达的就是这种释放兼容性。

本文的配置器没有实例独有的资源状态，同一元素类型的配置器实例使用相同的分配和释放机制，因此比较结果始终为真。比较不同元素类型的配置器时，可以把它理解为先按跨类型构造转到同一种配置器，再比较资源是否兼容。

```cpp
template <class U>
[[nodiscard]]
constexpr bool operator==(const allocator<U>&) const noexcept {
    return true;
}
```

## 2. 实现空间配置器适配器

设想我们在写容器，成员指针的类型该怎么声明？直接写 `T*`，容器就只能使用原生指针。直接写 `Alloc::pointer`，容器又要求每个配置器都写出这个别名，即使它本来只需要 `T*`。适配器把这次选择集中起来，容器只需使用 `allocator_traits<Alloc>::pointer`。

操作也是同样的思路。比如构造对象，配置器可能要参与这个过程，也可能只负责分配存储。容器仍然发出统一的调用，适配器根据配置器能提供的接口决定怎样完成它。

### 2.1 从 `pointer` 开始做类型萃取

`value_type` 直接从配置器取得，因为它是必需的。以 `pointer` 为例，缺省类型可以由 `value_type` 得到，也可以让配置器显式提供自己的指针类型。

![适配器中的基本关联类型](https://img.mdwind.online/img/20261111143614300.png)

先把这条选择规则写成一个独立的小例子。

```cpp
template <class Alloc, class = void>
struct pointer_type {
    using type = typename Alloc::value_type*;
};

template <class Alloc>
struct pointer_type<Alloc, std::void_t<typename Alloc::pointer>> {
    using type = typename Alloc::pointer;
};
```

写下 `pointer_type<Alloc>` 时，第二个模板参数默认是 `void`。匹配偏特化时，编译器尝试形成 `typename Alloc::pointer`。如果这个名字可以作为类型使用，`std::void_t` 就给出 `void`，偏特化成功匹配，采用配置器自己声明的 `pointer`。如果类型替换失败，这个偏特化会从本次匹配中排除，编译器改用主模板。这就是 SFINAE（替换失败并非错误）在这里的用法。两条路径都公开 `type`，外层只要读取 `pointer_type<Alloc>::type` 就能取得结果。

把这两条路径代入实际类型看。`wind::allocator<int>` 自己声明了 `pointer`，因此会走偏特化。如果另一个配置器只声明了 `using value_type = int;`，适配器仍然能得到 `int*`，只是这一次由主模板提供。两种写法得到的类型可以相同，选择顺序仍然有用。配置器给出自定义指针时，同一个选择器就会保留它。

完整实现把缺省规则放进了基类。选择器用主模板时，会继承基类公开的 `type`，外层仍用同一个名字取得结果。这里推导指针只需要配置器公开的 `value_type`，即使配置器的类模板有多个参数，也不用知道元素类型写在第几个位置。

```cpp
template <class Alloc>
struct allocator_pointer_traits {
    using type = typename Alloc::value_type*;
};

template <class Alloc, class = void>
struct allocator_pointer_traits_selector : allocator_pointer_traits<Alloc> {};

template <class Alloc>
struct allocator_pointer_traits_selector<Alloc, std::void_t<typename Alloc::pointer>> {
    using type = typename Alloc::pointer;
};
```

### 2.2 用指针重绑定保留自定义指针结构

确定 `pointer` 后，还要处理 `const_pointer`、`void_pointer` 和 `const_void_pointer`。如果指针是原生的，用相应的原生指针类型就能表示这些结果。配置器也可能使用自定义指针。例如，共享内存可以在不同进程里映射到不同的虚拟地址，这时指针可以保存相对偏移量，再在访问时计算当前进程里的地址。如果生成 `const_pointer` 时直接写成 `const int*`，这个偏移量就没有地方保存了。我们需要保留已有指针的地址表示方式，只改变它所指的类型。

假设配置器使用 `MyPointer<int>`，我们希望另外三种类型仍使用同一套地址表示方式，只改变所指类型。

```cpp
template <class T>
class MyPointer {};

using pointer = MyPointer<int>;
using const_pointer = MyPointer<const int>;
using void_pointer = MyPointer<void>;
using const_void_pointer = MyPointer<const void>;
```

这种做法叫作**重绑定（rebind）**。用偏特化演示这个过程时，可以分别匹配带一个类型参数的自定义指针和原生指针。

```cpp
template <class Ptr>
struct pointer_rebind;

// 自定义指针
template <template <class> class Ptr, class T>
struct pointer_rebind<Ptr<T>> {
    template <class U>
    using rebind = Ptr<U>;
};

// 原生指针
template <class T>
struct pointer_rebind<T*> {
    template <class U>
    using rebind = U*;
};
```

> **旁注**
>
> `class T` 接收一个类型，例如 `int` 或 `MyPointer<int>`。`template <class> class Ptr` 接收的是一个类模板，例如还没填入元素类型的 `MyPointer`。这样的参数叫模板模板参数。
>
> 用 `MyPointer<int>` 匹配 `Ptr<T>` 时，编译器分别推导出 `Ptr` 是 `MyPointer`、`T` 是 `int`。拿到 `Ptr` 后，就可以填入别的类型。比如 `rebind<const int>` 会形成 `MyPointer<const int>`。后面重绑定配置器时，`template <class, class...> class Alloc` 用的是同一个思路，还能接收跟在第一个类型参数后的一组类型参数。

原生指针那条偏特化直接把 `T*` 换成 `U*`。实际的自定义指针可能还有其他模板参数，也可能自己规定怎样重绑定。完整实现使用标准库的 `std::pointer_traits`。它也支持由指针类型自己提供重绑定规则。这里复用的是**指针适配器**，配置器的类型选择仍由自己的 `wind::allocator_traits` 完成。

```cpp
using const_pointer =
    typename std::pointer_traits<pointer>::template rebind<const value_type>;
using void_pointer =
    typename std::pointer_traits<pointer>::template rebind<void>;
using const_void_pointer =
    typename std::pointer_traits<pointer>::template rebind<const void>;
```

这三行给出的是各自的默认推导。配置器显式提供其中某种类型时，仍用 `std::void_t` 检测并优先采用它，三种类型分别选择。

![派生指针类型的选择](https://img.mdwind.online/img/20261112210854472.png)

![标准库中的关联类型萃取参考](https://img.mdwind.online/img/20261112211136801.png)

> **旁注**
>
> `Alloc::value_type` 和 `pointer_type<Alloc>::type` 都依赖模板参数 `Alloc`。用 `typename` 可以明确说明后面的限定名称表示类型。`std::pointer_traits<Pointer>::template rebind<U>` 中的 `template` 则标明 `rebind` 是模板，编译器据此解析后面的模板实参列表。
>
> 从 C++20 起，在类型别名右侧这样的类型上下文中，部分 `typename` 可以省略，例如 `using pointer = pointer_type<Alloc>::type;`。本文多数地方保留显式写法。`using type = std::is_empty<Alloc>::type;` 则用到了可以省略 `typename` 的规则。

### 2.3 确定差值和计数类型

有了指针，容器还可能需要表示两个元素之间相隔多少个位置。配置器自己提供 `difference_type` 时，直接采用。省略时，可以回到刚才选出的指针类型，请 `std::pointer_traits<Pointer>` 给出它的差值类型。原生指针对应 `std::ptrdiff_t`。如果自定义指针有自己的差值类型，这条规则就能沿用它。

再选 `size_type`。配置器没有显式提供时，用 `std::make_unsigned_t<Difference>` 取得差值类型对应的无符号类型。前面说过，两者都以元素为单位，一个表达带方向的位置差，一个用来计数。这里的依赖顺序就是先取指针，再确定差值类型，最后确定计数类型。

### 2.4 重绑定配置器及其适配器

回到双向链表的例子。容器已经持有一个为 `T` 准备空间的配置器。要构造节点配置器，还得先知道节点配置器是什么类型。`rebind_alloc<Node>` 给出这个类型，`rebind_traits<Node>` 则给出与它配套的适配器类型。

![配置器及其适配器的重绑定别名](https://img.mdwind.online/img/20261112211318210.png)

本例的 `wind::allocator<T>` 声明了 `rebind<U>::other`，直接把结果指定为 `wind::allocator<U>`。有了这项接口，配置器可以决定哪些参数要随元素类型一起变化。适配器通过 `rebind_alloc<U>` 取出它，再将结果传给 `allocator_traits` 得到 `rebind_traits<U>`。这两步在编译时确定类型。真正把已有配置器对象传过去，是之后构造节点配置器时要做的事。

省略显式接口时，适配器手头只有已经实例化的配置器类型。它可以从 `Alloc<T, Args...>` 中取出原模板，再填入 `Alloc<U, Args...>`。这一步有两个前提。第一，配置器能匹配「一个类型参数，后面跟零个或多个类型参数」的形状。第二，第一个类型参数就是要替换的元素类型，后面的类型参数可以原样保留。模板能匹配，只说明它具有这个形状。第一个位置的实际含义得由配置器遵守这个约定。

这和推导 `pointer` 时遇到的问题不同。推导指针只要知道元素是哪一种类型，读取 `value_type` 就够了。重绑定要重新形成整个配置器类型，即使知道 `value_type`，也无法从这个别名判断应该替换哪个参数，或者哪些参数要跟着变化。元素类型放在别处、模板含有非类型参数，或其他参数也依赖元素类型时，就可以通过显式的 `rebind<U>::other` 把重绑定规则告诉适配器。

![配置器重绑定的默认实现和选择器](https://img.mdwind.online/img/20261112211602164.png)

![配置器重绑定相关代码](https://img.mdwind.online/img/20261112212416879.png)

> **旁注**
>
> 指针重绑定和配置器重绑定的目标都是得到一个新类型，处理的对象各不相同。前者从已有指针类型得到指向另一种元素的指针类型，后者从已有配置器类型得到用于另一种元素的配置器类型。确定了配置器类型之后，还可以用它形成新的适配器类型。

### 2.5 转发操作与补齐默认实现

申请和释放的接口里，有一个参数是配置器对象本身。例如 `Traits::allocate(alloc, n)` 最终调用 `alloc.allocate(n)`。`Traits` 只负责统一调用方式，真正知道要从哪个资源取空间的是 `alloc`。传引用可以让操作用到容器当前持有的那个配置器对象。

构造对象时，我们手头已经有地址和构造参数。先问一句，这个配置器对象能不能用**这组参数**完成构造？代码里的 `requires { alloc.construct(p, std::forward<Args>(args)...); }` 检查的就是这个表达式能否成立。即使配置器里有个名为 `construct` 的成员，参数对不上也会走缺省分支。表达式本身只参与检查，真正的构造在选中的分支里执行一次。

以 `wind::allocator<int>` 为例，传入 `int*` 和可用于构造 `int` 的参数时，适配器会调用配置器自己的 `construct`，最终由 `std::construct_at` 在指定地址构造对象。配置器省略这项操作时，适配器可以直接调用 `std::construct_at`。销毁也是同一个判断过程，能调用 `alloc.destroy(p)` 就用它，否则使用 `std::destroy_at(p)`。

两项辅助操作接收的都是 `const allocator_type&`。查询上限只需要读取信息。为新容器选择配置器时，适配器也可以通过只读引用访问源配置器，再按值返回选择出的配置器对象。这里的 `requires` 检查的是这两个调用在 `const` 引用上能否成立。

- **查询数量上限。** 本例的 `max_size() const noexcept` 可以通过这个引用调用，所以适配器直接取得配置器算好的 `max_element_count`。如果调用不成立，适配器才按 `std::numeric_limits<size_type>::max() / sizeof(value_type)` 计算上限。
- **为拷贝构造容器选择配置器。** 用已有容器构造一个新容器时，需要先决定新容器用哪个配置器来准备空间。本例的 `select_on_container_copy_construction() const noexcept` 按值返回 `*this`，也就是用源配置器拷贝构造返回对象。适配器能通过 `const` 引用调用它，所以采用配置器自己的选择规则。如果调用不成立，适配器会自行拷贝源配置器。

### 2.6 配置器的传播策略

同一个容器类型的两个对象可以持有同类型的配置器，却分别关联不同的内存池。给一个已有容器赋值，或交换两个容器时，就要确定配置器本身是否跟着变化。适配器公开三项类型供容器判断。

| 容器操作                    | 对应的传播类型                           | 值为 `true` 时           |
| --------------------------- | ---------------------------------------- | ------------------------ |
| 拷贝赋值 `a = b`            | `propagate_on_container_copy_assignment` | 拷贝赋值目标容器的配置器 |
| 移动赋值 `a = std::move(b)` | `propagate_on_container_move_assignment` | 移动赋值目标容器的配置器 |
| 交换 `a.swap(b)`            | `propagate_on_container_swap`            | 交换两个容器的配置器     |

三项的默认类型都是 `std::false_type`，也就是默认保留容器各自的配置器。拿移动赋值 `a = std::move(b)` 来看，假设 `b` 的存储空间来自池 B。如果允许传播，`a` 可以先用自己的旧配置器处理原有空间，再接过 `b` 的配置器和存储空间。以后释放接过来的空间时，仍然能归还给池 B。

如果 `a` 保留自己的配置器，它就得先确认这个配置器能否释放 `b` 那块空间。可以释放，就有条件接管原来的存储。如果两个池互不兼容，`a` 就得在自己能管理的存储空间里逐个迁移元素。对标准库的配置器感知容器，交换时若配置器不传播，则要求两个配置器相等。拷贝赋值是否传播决定配置器是否跟着变，元素仍要按拷贝语义处理。

如果同一类型的配置器随便取出两个都能互相释放对方取得的空间，容器就可以在编译时知道这项兼容性。`is_always_equal` 用来表达这项保证。

想想两个配置器为什么会不相等。前面的例子里，两个实例各自保存了一个内存池的关联，同样调用释放操作，实际归还的地方却不同。本文的 `wind::allocator<T>` 是空类，实例里没有池指针之类的私有资源状态。对同一个 `T`，两个实例调用的是同一套全局分配与释放函数，也会根据相同的对齐条件选中同一组重载。哪个实例发起申请，对以后如何归还这块空间没有影响，因此这些实例相互兼容。

这也解释了为什么适配器缺省时用空类检测。没有实例状态，通常就没有因实例不同而改变的资源归属。配置器如果显式声明了 `is_always_equal`，适配器优先采用这个声明。

```cpp
using type = std::is_empty<Alloc>::type;
```

`is_always_equal::value` 为 `true` 时，这个保证适用于任意一对实例。值为 `false` 时，仍可以用相等运算符判断手头的两个实例是否兼容。

> **旁注**
>
> 直接把 `std::is_empty<Alloc>` 用作默认类型，读取 `::value` 时也会得到同一个布尔值。原因是 `std::is_empty<Alloc>` 继承自 `std::true_type` 或 `std::false_type`。直接取 `::value`，或者先通过 `::type` 取得基类类型再取 `::value`，访问的是同一个静态成员。
>
> C++20 对默认关联类型指定的是 `std::is_empty<Alloc>::type`，也就是确切的 `std::true_type` 或 `std::false_type`。如果直接公开检测类，只读取 `::value` 的代码仍能工作，但公开的类型会和接口要求不同。

这些策略通过类型公开，调用方既能读取它们的编译期常量 `value`，也能把结果类型用在其他模板代码里。例如，容器可以通过 `if constexpr (Traits::propagate_on_container_move_assignment::value)` 在编译时选择是否移动赋值配置器。具体怎样处理元素和存储空间，由容器实现。

### 3.1 空间配置器

```cpp
#pragma once

#include <concepts>
#include <cstddef>
#include <limits>
#include <memory>
#include <new>
#include <utility>

namespace wind {

template <class T>
class allocator {
public:
    using value_type = T;
    using pointer = value_type*;
    using const_pointer = const value_type*;
    using size_type = std::size_t;
    using difference_type = std::ptrdiff_t;
    using byte_size_type = std::size_t;

    template <class U>
    struct rebind {
        using other = allocator<U>;
    };

private:
    static constexpr size_type max_element_count =
        std::numeric_limits<byte_size_type>::max() / sizeof(T);

public:
    allocator() noexcept = default;

    template <class U>
        requires (!std::same_as<T, U>)
    allocator(const allocator<U>&) noexcept {}

    [[nodiscard]]
    T* allocate(size_type n) {
        if (n > max_element_count) {
            throw std::bad_array_new_length{};
        }

        const byte_size_type bytes = n * sizeof(T);

        if constexpr (alignof(T) > __STDCPP_DEFAULT_NEW_ALIGNMENT__) {
            return static_cast<T*>(::operator new(bytes, std::align_val_t{alignof(T)}));
        } else {
            return static_cast<T*>(::operator new(bytes));
        }
    }

    void deallocate(T* p, [[maybe_unused]] size_type n) noexcept {
        if constexpr (alignof(T) > __STDCPP_DEFAULT_NEW_ALIGNMENT__) {
            ::operator delete(p, std::align_val_t{alignof(T)});
        } else {
            ::operator delete(p);
        }
    }

    size_type max_size() const noexcept {
        return max_element_count;
    }

    template <class... Args>
    void construct(pointer p, Args&&... args) {
        std::construct_at(p, std::forward<Args>(args)...);
    }

    void destroy(pointer p) {
        std::destroy_at(p);
    }

    allocator<T> select_on_container_copy_construction() const noexcept {
        return *this;
    }

    template <class U>
    [[nodiscard]]
    constexpr bool operator==(const allocator<U>&) const noexcept {
        return true;
    }
};

}  // namespace wind
```

### 3.2 空间配置器适配器

```cpp
#pragma once

#include <cstddef>
#include <limits>
#include <memory>
#include <type_traits>
#include <utility>

namespace wind {

// 配置器指针萃取
template <class Alloc>
struct allocator_pointer_traits {
    using type = typename Alloc::value_type*;
};

template <class Alloc, class = void>
struct allocator_pointer_traits_selector : allocator_pointer_traits<Alloc> {};

template <class Alloc>
struct allocator_pointer_traits_selector<Alloc, std::void_t<typename Alloc::pointer>> {
    using type = typename Alloc::pointer;
};

// 指向常量的指针类型选择
template <class Alloc, class Value, class Pointer, class = void>
struct allocator_const_pointer_selector {
    using type = typename std::pointer_traits<Pointer>::template rebind<const Value>;
};

template <class Alloc, class Value, class Pointer>
struct allocator_const_pointer_selector<Alloc, Value, Pointer,
                                        std::void_t<typename Alloc::const_pointer>> {
    using type = typename Alloc::const_pointer;
};

// 指向 void 的指针类型选择
template <class Alloc, class Pointer, class = void>
struct allocator_void_pointer_selector {
    using type = typename std::pointer_traits<Pointer>::template rebind<void>;
};

template <class Alloc, class Pointer>
struct allocator_void_pointer_selector<Alloc, Pointer, std::void_t<typename Alloc::void_pointer>> {
    using type = typename Alloc::void_pointer;
};

// 指向 const void 的指针类型选择
template <class Alloc, class Pointer, class = void>
struct allocator_const_void_pointer_selector {
    using type = typename std::pointer_traits<Pointer>::template rebind<const void>;
};

template <class Alloc, class Pointer>
struct allocator_const_void_pointer_selector<Alloc, Pointer,
                                             std::void_t<typename Alloc::const_void_pointer>> {
    using type = typename Alloc::const_void_pointer;
};

// 配置器类型重绑定
template <class Alloc, class U>
struct allocator_rebind;

// 提取原配置器模板，并替换第一个类型参数
template <class U, template <class, class...> class Alloc, class T, class... Args>
struct allocator_rebind<Alloc<T, Args...>, U> {
    using type = Alloc<U, Args...>;
};

// 优先使用配置器自身提供的重绑定规则
template <class Alloc, class U, class = void>
struct allocator_rebind_selector : allocator_rebind<Alloc, U> {};

template <class Alloc, class U>
struct allocator_rebind_selector<Alloc, U, std::void_t<typename Alloc::template rebind<U>::other>> {
    using type = typename Alloc::template rebind<U>::other;
};

// 偏移量类型萃取
template <class Alloc, class Pointer, class = void>
struct allocator_difference_type_traits {
    // 缺省时，从已选定的指针类型取得差值类型
    using type = typename std::pointer_traits<Pointer>::difference_type;
};

template <class Alloc, class Pointer>
struct allocator_difference_type_traits<Alloc, Pointer,
                                        std::void_t<typename Alloc::difference_type>> {
    using type = typename Alloc::difference_type;
};

// 数量类型萃取
template <class Alloc, class Difference, class = void>
struct allocator_size_type_traits {
    // 数量类型默认使用偏移量的无符号版本
    using type = std::make_unsigned_t<Difference>;
};

template <class Alloc, class Difference>
struct allocator_size_type_traits<Alloc, Difference, std::void_t<typename Alloc::size_type>> {
    using type = typename Alloc::size_type;
};

// 拷贝传播类型萃取
template <class Alloc, class = void>
struct allocator_copy_propagation_traits {
    using type = std::false_type;
};

template <class Alloc>
struct allocator_copy_propagation_traits<
    Alloc, std::void_t<typename Alloc::propagate_on_container_copy_assignment>> {
    using type = typename Alloc::propagate_on_container_copy_assignment;
};

// 移动语义传播类型萃取
template <class Alloc, class = void>
struct allocator_move_propagation_traits {
    using type = std::false_type;
};

template <class Alloc>
struct allocator_move_propagation_traits<
    Alloc, std::void_t<typename Alloc::propagate_on_container_move_assignment>> {
    using type = typename Alloc::propagate_on_container_move_assignment;
};

// 内容交换传播类型萃取
template <class Alloc, class = void>
struct allocator_swap_propagation_traits {
    using type = std::false_type;
};

template <class Alloc>
struct allocator_swap_propagation_traits<Alloc,
                                         std::void_t<typename Alloc::propagate_on_container_swap>> {
    using type = typename Alloc::propagate_on_container_swap;
};

// 恒等性类型萃取
template <class Alloc, class = void>
struct allocator_always_equal_traits {
    // 缺省时，使用空类检测给出的布尔常量类型
    using type = std::is_empty<Alloc>::type;
};

template <class Alloc>
struct allocator_always_equal_traits<Alloc, std::void_t<typename Alloc::is_always_equal>> {
    using type = typename Alloc::is_always_equal;
};

template <class Alloc>
struct allocator_traits {
   public:
    // 配置器基本类型
    using allocator_type = Alloc;
    using value_type = typename allocator_type::value_type;

    // 指针类型
    using pointer = typename allocator_pointer_traits_selector<allocator_type>::type;
    using const_pointer =
        typename allocator_const_pointer_selector<allocator_type, value_type, pointer>::type;
    using void_pointer = typename allocator_void_pointer_selector<allocator_type, pointer>::type;
    using const_void_pointer =
        typename allocator_const_void_pointer_selector<allocator_type, pointer>::type;

    // 数量与差值类型
    using difference_type =
        typename allocator_difference_type_traits<allocator_type, pointer>::type;
    using size_type = typename allocator_size_type_traits<allocator_type, difference_type>::type;

    // 描述传播类型特性的类型接口
    using propagate_on_container_copy_assignment =
        typename allocator_copy_propagation_traits<Alloc>::type;
    using propagate_on_container_move_assignment =
        typename allocator_move_propagation_traits<Alloc>::type;
    using propagate_on_container_swap = typename allocator_swap_propagation_traits<Alloc>::type;
    using is_always_equal = typename allocator_always_equal_traits<Alloc>::type;

   public:
    // 配置器类型重绑定
    template <class U>
    using rebind_alloc = typename allocator_rebind_selector<allocator_type, U>::type;

    template <class U>
    using rebind_traits = allocator_traits<rebind_alloc<U>>;

   public:
    // 原始内存管理
    [[nodiscard]]
    static pointer allocate(allocator_type& alloc, size_type n) {
        return alloc.allocate(n);
    }

    static void deallocate(allocator_type& alloc, pointer p, size_type n) {
        alloc.deallocate(p, n);
    }

   public:
    // 对象生命周期管理
    template <class T, class... Args>
    static void construct(Alloc& alloc, T* p, Args&&... args) {
        if constexpr (requires { alloc.construct(p, std::forward<Args>(args)...); }) {
            alloc.construct(p, std::forward<Args>(args)...);
        } else {
            std::construct_at(p, std::forward<Args>(args)...);
        }
    }

    template <class T>
    static void destroy(Alloc& alloc, T* p) {
        if constexpr (requires { alloc.destroy(p); }) {
            alloc.destroy(p);
        } else {
            std::destroy_at(p);
        }
    }

   public:
    // 配置器辅助操作
    static size_type max_size(const allocator_type& alloc) noexcept {
        if constexpr (requires { alloc.max_size(); }) {
            return alloc.max_size();
        } else {
            return std::numeric_limits<size_type>::max() / sizeof(value_type);
        }
    }

    static Alloc select_on_container_copy_construction(const allocator_type& alloc) {
        if constexpr (requires { alloc.select_on_container_copy_construction(); }) {
            return alloc.select_on_container_copy_construction();
        } else {
            return alloc;
        }
    }
};

}  // namespace wind
```
