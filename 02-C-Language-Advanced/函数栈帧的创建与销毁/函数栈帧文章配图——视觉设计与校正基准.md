# 函数栈帧文章配图：视觉设计与校正基准（第一版）

## 目标与适用范围

适用于 `main` 栈帧建立、`Add` 调用与返回、`main` 返回及涉及 libc 的实验配图。目标是让读者沿着正文叙述顺序识别当前指令、观察状态变化、理解因果关系，同时不歪曲实验事实。

## 一、四项核心原则

1. **真实性优先于视觉效果。** 寄存器数值、地址、内存内容、指令顺序及执行状态必须与实验记录一致。可以裁剪、淡化、局部放大和重排，但不得伪造数据、清零历史内容，或将尚未执行的指令效果画成已发生。
2. **当前问题决定视觉重点。** 同一数据在不同阶段可以从背景变成焦点。例如旧 `%rbp` 在建帧时是必要上下文，在恢复调用者栈帧时成为当前焦点；数值与语义不随视觉权重变化。
3. **多种视觉手段分工明确。** 明度区分主次，颜色区分语义，边框限定范围，箭头表示方向，布局提供上下文，前后对照展示变化。不要让所有元素同时高亮。
4. **正文与附录信息密度不同。** 正文服务于概念理解；附录保留完整逐指令记录。简化呈现不等于简化事实。

## 二、统一视觉层级

| 层级 | 内容 | 表现 |
| --- | --- | --- |
| 一级：当前焦点 | 当前指令直接改变的寄存器、内存或控制流 | 高对比度，必要时使用边框、箭头或局部放大 |
| 二级：必要上下文 | 当前帧边界、保存的旧 `%rbp`、相关返回地址 | 正常明度，稳定语义颜色 |
| 三级：历史背景 | 调用者的其他栈数据、历史残留内容 | 低对比度、弱化边框和注释，仍可核对 |
| 四级：暂不涉及 | 与当前问题无关的 libc 内部细节等 | 可折叠、省略显示或转入附录 |

**淡化、折叠或省略显示均不表示清零、释放或失效。** 不连续的内存区域不得直接拼成连续布局；须用断裂符号或文字说明省略范围。

## 三、视觉手段的分工

| 手段 | 应当做到 | 避免 |
| --- | --- | --- |
| 颜色 | 同一类对象全篇语义稳定 | 每张图为强调而随意换色 |
| 明度 | 焦点突出，背景可辨认 | 淡化到无法核对 |
| 边框 | 精确圈定指令影响范围 | 大面积粗框掩盖实际操作范围 |
| 箭头 | 区分寄存器指向、数值变化、数据流向 | 含义不明或混淆方向的箭头 |
| 局部放大 | 保留原地址与局部位置的对应关系 | 只剩孤立的数值，失去整体定位 |
| 前后对照 | 同尺度、同方向、同地址刻度 | 通过变换比例造成假位移 |
| 标注 | 解释图形本身无法表达的事实 | 重复正文或提前引入无关机制 |

语义配色与焦点强调分离：例如 `%rbp` 保持稳定的身份颜色，需要强调时使用轮廓或对比度，而不是改换身份颜色。

## 四、时间与状态约定

- 明确区分**即将执行**、**正在解释的指令**与**执行后的状态**。箭头停在某条指令上，不自动意味着该指令已经执行。
- 对每个状态注明实验步号及关键指令；必要时明确“执行前 / 执行后”。
- 前后状态比较时，尽量保持相同的地址范围、比例、排列方向和语义颜色，只改变真实发生变化的部分。
- 不要把“寄存器移动”画成“内存整体搬迁”；`subq $0x10, %rsp` 改变栈指针，不会自动写入或清零 16 字节。
- 区分内存**内容仍存在**与该区域**仍归当前活动栈帧使用**；两者不是一回事。
- 由推断重建而非实际单步观测的状态，必须明确标记，不得与实测图混同。

## 五、正文图的最小信息集

每张图原则上应能回答四个问题：

1. **现在在哪里？** 当前函数、指令与执行前后状态。
2. **关注什么？** 受影响的寄存器、地址或内存区域。
3. **变化是什么？** 数值、指向、栈空间边界或控制流的变化。
4. **如何核对？** 足够的真实地址、寄存器值或与原始实验记录的对应关系。

正文可保留保存的旧 `%rbp`、返回地址及当前局部空间等后续解释所必需的伏笔；不应因当前暂时无关就完全删除这些关系。

## 六、第三阶段的具体应用

| 实验步骤 | 指令 | 重点表现 | 处理建议 |
| --- | --- | --- | --- |
| 63→64 | `callq *%rax` | 返回地址入栈、`%rsp` 变化、控制流进入 `main` | 前后对照，保留调用关系，淡化 libc 其他栈数据 |
| 64→65 | `pushq %rbp` | 旧帧指针写入栈内，`%rsp` 减少 8 字节，`%rbp` 尚未改变 | 突出新写入的 8 字节和指针位置 |
| 65→66 | `movq %rsp, %rbp` | 帧基准建立；栈内存不变 | 重点改变寄存器标记，不制造内存变化 |
| 66→67 | `subq $0x10, %rsp` | 预留 16 字节；内容不因该指令清零 | 突出新范围、指针变化，保留原有内容或标明未写入 |
| 67→68 | `movl $0x0, -0x4(%rbp)` | 编译器使用的额外栈槽被写入 | 简述，避免误称为所有 C 函数通用的返回值传递机制 |
| 68→69 | `movl $0xa, -0x8(%rbp)` | `a=10` 的具体地址和 4 字节写入 | 重点演示 `%rbp` 相对寻址 |
| 69→70 | `movl $0x14, -0xc(%rbp)` | `b=20` 的写入 | 简述，同一尺度延续 |
| 70→71 | `movl $0x0, -0x10(%rbp)` | `c=0` 的写入 | 应补齐执行后的实测状态图，再作为阶段结束图 |

**注意：第 70 步截图中箭头指向 `c` 初始化指令，不能据此断言该指令已经执行。**

## 七、图像审查清单

- [ ] 图中指令与标记的状态（执行前/后）一致。
- [ ] 所有关键地址、寄存器数值和内存内容可与实验记录对应。
- [ ] 当前焦点能在第一眼被定位。
- [ ] 历史内容未被伪装为零、空白或已清除。
- [ ] 颜色语义与前后图片一致。
- [ ] 箭头、边框和放大范围分别表达明确含义。
- [ ] 同一过程的连续图保持尺度、地址方向和坐标稳定。
- [ ] 省略和裁剪不会制造错误的地址连续性。
- [ ] 图片没有提前解释当前阶段不需要的机制。
- [ ] 正文能独立理解，附录仍可用于完整核验。

## 八、验收标准

**合格的正文配图，应让读者先看到当前变化，再理解它在栈帧中的位置，最后能够按需追溯历史状态。**

如果一张图必须先解释大量历史细节才能看懂当前指令，就应重新调整视觉层级；如果简化后无法还原关键事实，则应恢复必要上下文，而不是牺牲准确性。

本基准先用于第 64～67 步样板验证，确认后再统一推广到 `Add` 的建帧、返回及 `main` 的返回阶段。
