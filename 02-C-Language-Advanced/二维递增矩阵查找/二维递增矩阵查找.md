# 二维递增矩阵查找

题目条件：

> 有一个数字矩阵，矩阵中的元素从左到右递增、从上到下递增。  
> 编写程序判断某个数字是否存在于该矩阵中。

本文只整理两个与这道题直接相关的知识点：

1. 二维数组的动态开辟方式，以及它与函数签名之间的类型适配；
2. 利用矩阵双向递增性质进行阶梯查找。

---

## 一、二维数组的动态开辟与函数签名适配

### 1. 真正的二维数组本质上是一块连续内存

例如：

```c
int arr[4][5];
```

其内存并不是“4 个彼此独立的一维数组”，而是一整块连续区域：

```text
arr
 ↓
+-------------------+-------------------+-------------------+-------------------+
|      第 0 行       |      第 1 行       |      第 2 行       |      第 3 行       |
+-------------------+-------------------+-------------------+-------------------+
| 5 个 int          | 5 个 int          | 5 个 int          | 5 个 int          |
+-------------------+-------------------+-------------------+-------------------+
```

因此从地址计算上看：

```c
arr[i][j]
```

本质就是：

```text
首地址 + (i * 5 + j) * sizeof(int)
```

关键在于：编译器必须知道“一行有多少个元素”。

对于：

```c
int arr[4][5];
```

这个信息是 `5`。

---

### 2. 二维数组退化后并不是 `int **`

这一点很容易因为 `arr[i][j]` 的写法而产生错觉。

二维数组：

```c
int arr[4][5];
```

在大多数表达式中退化后，其类型是：

```c
int (*)[5]
```

即：

```text
指向 int[5] 的指针
```

而不是：

```c
int **
```

二者虽然都能写出类似：

```c
arr[i][j]
```

的形式，但底层类型结构完全不同。

---

### 3. `int **` 的典型内存模型

如果使用：

```c
int **arr;
```

通常对应的是：

```text
arr
 ↓
+-------+-------+-------+
| ptr   | ptr   | ptr   |
+-------+-------+-------+
   ↓       ↓       ↓
 [一行]  [一行]  [一行]
```

也就是说：

```c
arr[i]
```

本身必须是一个有效的 `int *`。

因此下面这种写法是错误的：

```c
int **arr = malloc(sizeof(int) * m * n);
```

因为申请出来的是一块连续的 `int` 空间，却把它解释成了若干个 `int *`。

随后访问：

```c
arr[i][j]
```

时，程序会先把内存中的数据解释成指针：

```c
arr[i]
```

再沿着这个“指针”继续访问，结果自然很容易出现段错误。

---

### 4. 如果想要连续内存，应使用“数组指针”

对于运行时才能确定列数 `n` 的矩阵，可以写：

```c
int (*arr)[n] = malloc(sizeof *arr * m);
```

这里：

```c
int (*arr)[n];
```

不是指针数组，而是：

```text
arr 是一个指针
arr 指向 int[n]
```

即：

```text
指向“一整行”的指针
```

与下面这个声明完全不同：

```c
int *arr[n];
```

后者才是：

```text
包含 n 个 int * 的数组
```

二者只差一对括号，但类型完全不同。

---

### 5. 为什么 `malloc(sizeof *arr * m)` 正好开出整个矩阵

对于：

```c
int (*arr)[n];
```

有：

```c
*arr
```

其类型为：

```c
int[n]
```

因此：

```c
sizeof *arr
```

等价于：

```c
sizeof(int[n])
```

即一整行所占的字节数：

```text
n * sizeof(int)
```

再乘以 `m`：

```c
malloc(sizeof *arr * m);
```

实际申请：

```text
m * n * sizeof(int)
```

字节。

因此最终得到的仍然是一整块连续内存：

```text
arr
 ↓
+-----------+-----------+-----------+-----------+
| 第 0 行    | 第 1 行    | 第 2 行    | ...       |
+-----------+-----------+-----------+-----------+
```

只是此时类型系统知道：

> 每跨过一个 `arr` 元素，就是跨过一整行 `int[n]`。

所以：

```c
arr + 1
```

移动的不是一个 `int`，也不是一个指针大小，而是：

```text
n * sizeof(int)
```

字节。

于是：

```c
arr[i][j]
```

便能够自然成立。

---

### 6. `sizeof` 不一定要写括号

这里顺带补充一个容易被习惯掩盖的语法点。

`sizeof` 是一元运算符，处理表达式时可以写：

```c
sizeof expression
```

因此：

```c
sizeof *arr
```

等价于：

```c
sizeof(*arr)
```

只有操作对象是“类型名”时，括号才是语法要求：

```c
sizeof(int)
sizeof(double)
sizeof(int[n])
```

因此：

```c
malloc(sizeof *arr * m);
```

可以理解为：

```c
malloc(sizeof(*arr) * m);
```

只是省掉了表达式外层不必要的括号。

---

### 7. 函数签名如何适配运行时列数

由于 `n` 决定了：

```c
int (*)[n]
```

中的“每行长度”，所以函数声明时必须先让 `n` 进入作用域。

可以写：

```c
bool searchInSortedMatrix(
    int m,
    int n,
    int (*arr)[n],
    int k
);
```

这里参数是按顺序声明的。

当编译器处理：

```c
int (*arr)[n]
```

时，前面的：

```c
int n
```

已经存在，因此可以用于后续参数的类型声明。

也可以写成更像二维数组的形式：

```c
bool searchInSortedMatrix(
    int m,
    int n,
    int arr[m][n],
    int k
);
```

但在函数参数中：

```c
int arr[m][n]
```

会调整为：

```c
int (*arr)[n]
```

所以真正决定类型的是第二维 `n`。

因此以下形式本质一致：

```c
int (*arr)[n]
```

```c
int arr[][n]
```

```c
int arr[m][n]
```

在这道题中，我更倾向直接使用：

```c
bool searchInSortedMatrix(
    int m,
    int n,
    int (*arr)[n],
    int k
);
```

因为它把真实的参数类型直接写出来了。

---

### 8. 完整的动态矩阵模型

开辟：

```c
int (*arr)[n] = malloc(sizeof *arr * m);
```

访问：

```c
arr[i][j]
```

传参：

```c
searchInSortedMatrix(m, n, arr, k);
```

函数：

```c
bool searchInSortedMatrix(
    int m,
    int n,
    int (*arr)[n],
    int k
);
```

释放：

```c
free(arr);
```

这里只进行了一次 `malloc`，所以也只需要一次 `free`。

这与每一行分别 `malloc` 的 `int **` 方案不是一套内存模型。

## 二、阶梯查找

矩阵满足：

```text
从左到右递增  →
从上到下递增  ↓
```

例如：

```text
 1   4   7  11  15
 2   5   8  12  19
 3   6   9  16  22
10  13  14  17  24
```

乍看它是二维的，因此不能像普通一维有序数组那样直接进行一次标准二分查找。

真正关键的问题不是：

> 怎么在二维数组里二分？

而是：

> 能不能找到一个位置，使一次比较就能确定地排除一整块候选区域？

右上角正好具有这种性质。

---

### 1. 为什么选择右上角

设当前位置为：

```text
arr[i][j] = x
```

并且当前位置位于当前搜索区域的右上角。

此时：

```text
左边的元素 ≤ x
下面的元素 ≥ x
```

也就是说，当前位置同时连接了两个方向：

```text
← 更小        x
              ↓
             更大
```

这让一次比较具备了明确的排除方向。

---

### 2. 当 `x > k`

如果：

```c
arr[i][j] > k
```

由于同一列向下递增，所以：

```text
arr[i][j]
arr[i+1][j]
arr[i+2][j]
...
```

只会越来越大。

既然当前元素已经大于目标值 `k`，那么这一列从当前位置开始向下的所有元素都不可能等于 `k`。

因此这一列可以彻底排除：

```c
--j;
```

即向左移动一列。

---

### 3. 当 `x < k`

如果：

```c
arr[i][j] < k
```

由于当前元素位于这一行搜索区域的最右侧，而这一行从左到右递增，所以这一行剩余元素都满足：

```text
≤ arr[i][j] < k
```

因此这一整行都不可能再出现 `k`。

可以直接排除当前行：

```c
++i;
```

即向下移动一行。

---

### 4. 当 `x == k`

直接找到：

```c
return true;
```

---

### 5. 搜索路径为什么像“阶梯”

算法从右上角开始：

```text
             起点
               ↓
[ ][ ][ ][ ][■]
[ ][ ][ ][■][ ]
[ ][ ][ ][■][ ]
[ ][ ][■][ ][ ]
[ ][ ][■][ ][ ]
```

每次只会做两种移动：

```text
向左
向下
```

因此路径整体呈现阶梯状，这也是阶梯查找（staircase search）这个名称的来源。

---

### 6. 为什么不能从左上角开始

左上角虽然看起来也是一个自然起点，但它不具备确定的排除方向。

假设：

```text
x = arr[0][0]
```

如果：

```text
x < k
```

那么：

```text
右边可能存在 k
下面也可能存在 k
```

两个方向都仍然有可能，无法确定应该舍弃哪一边。

右下角同理。

真正有用的是：

```text
右上角
左下角
```

因为这两个位置的两个可移动方向分别具有“一边更小、一边更大”的关系。

从左下角开始也可以得到完全对称的算法：

```text
当前值 > k  -> 向上
当前值 < k  -> 向右
```

本质与右上角方案相同。

---

### 7. 最终算法

```c
bool searchInSortedMatrix(int m, int n, int (*arr)[n], int k)
{
    int i = 0;
    int j = n - 1;

    while (i < m && j >= 0) {
        if (arr[i][j] > k)
            --j;
        else if (arr[i][j] < k)
            ++i;
        else
            return true;
    }

    return false;
}
```

---

### 8. 复杂度

搜索从右上角：

```text
(0, n - 1)
```

开始。

每一步不是：

```text
j - 1
```

就是：

```text
i + 1
```

也就是说，每一步都会永久排除一列或一行，不会回头。

最多移动：

```text
(n - 1) 次向左
+
(m - 1) 次向下
```

再加上起点本身的比较，因此最多检查：

```text
m + n - 1
```

个位置。

时间复杂度：

```text
O(m + n)
```

额外空间复杂度：

```text
O(1)
```

---

## 三、这道题真正值得记住的两个点

这道题本身代码很短，真正容易遗忘的反而不是代码。

第一，二维连续数组的类型不是 `int **`。

如果矩阵是一整块连续内存，并且每行有 `n` 个 `int`，与它自然匹配的指针类型是：

```c
int (*)[n]
```

第二，阶梯查找真正的核心不是“从右上角开始”这个结论，而是：

> 选择一个位置，使当前位置与两个搜索方向分别形成一大一小的单调关系。这样一次比较之后，就一定能彻底排除一整行或一整列。

因此这个算法本质上仍然是在不断缩小搜索空间。

只是这里每次缩小的不是一维区间，而是二维矩阵中的一行或一列。
