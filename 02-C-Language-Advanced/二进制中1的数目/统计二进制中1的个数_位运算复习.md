# 统计整数二进制表示中 `1` 的个数

## 1. 问题

目标：给定一个整数，统计它的二进制表示中一共有多少个 `1`。

例如：

```text
103₁₀ = 1100111₂
```

其中一共有 5 个 `1`，所以结果应当是：

```text
5
```

这个问题可以有很多种做法。这里主要记录第三种方法：

```c
n = n & (n - 1);
```

它每执行一次，就会清除当前二进制数中最低位的那个 `1`。

在重新理解这种方法之前，也顺便记录一下第一种“除 2 取余”的方法，因为我这次复习时犯了一个很基础、但很典型的方向错误。

---

## 2. 第一种方法：除 2 取余

十进制整数转换成二进制，可以不断除以 2，并记录余数。

以 `103` 为例：

```text
103 / 2 = 51  余 1
 51 / 2 = 25  余 1
 25 / 2 = 12  余 1
 12 / 2 =  6  余 0
  6 / 2 =  3  余 0
  3 / 2 =  1  余 1
  1 / 2 =  0  余 1
```

按计算产生的顺序，余数是：

```text
1 1 1 0 0 1 1
```

但这个顺序实际上是：

```text
最低位 → 最高位
```

因此真正写成通常阅读的二进制形式时，需要反过来：

```text
1100111
```

也就是：

```text
103₁₀ = 1100111₂
```

### 我这次犯的错误

我虽然正确算出了：

```text
1100111
```

但太久没碰位操作之后，下意识把最左边的 `1` 当成了最低位。

实际上通常书写二进制数时：

```text
1100111
↑     ↑
最高位 最低位
```

和十进制完全一样。

例如十进制：

```text
1234
↑  ↑
千位 个位
```

二进制也仍然是“高位在左，低位在右”。

因此：

```text
1100111₂
```

展开应该是：

```text
1×2⁶ + 1×2⁵ + 0×2⁴ + 0×2³ + 1×2² + 1×2¹ + 1×2⁰
```

也就是：

```text
64 + 32 + 4 + 2 + 1 = 103
```

我之前总是核对不上的根本原因，并不是除 2 取余算错了，而是把二进制位的方向看反了。

## 3. 第三种方法：不断清除最低位的 `1`

核心操作：

```c
n = n & (n - 1);
```

它有一个非常有用的性质：

> 对任意非零整数 `n`，`n & (n - 1)` 会恰好清除 `n` 二进制表示中最低位的那个 `1`。

因此可以写成：

```c
int count_ones_by_clearing(unsigned int n)
{
    int count = 0;

    while (n) {
        count++;
        n &= n - 1;
    }

    return count;
}
```

循环执行多少次，就说明原来的二进制表示中有多少个 `1`。

---

## 4. 为什么 `n & (n - 1)` 能清掉一个 `1`

关键不是死记公式，而是观察：

```text
n - 1
```

到底会对二进制产生什么影响。

假设：

```text
n = 1011000
```

从右往左看，最低位的 `1` 在这里：

```text
1011000
   ↑
```

它右边全部都是 `0`。

现在减去 `1`：

```text
1011000
      -1
-------
1010111
```

可以把这个变化拆成两部分：

```text
101 | 1000
101 | 0111
```

左边的：

```text
101
```

完全没有受到影响。

右边则从：

```text
1000
```

变成：

```text
0111
```

也就是说：

1. 原来最低位的那个 `1` 变成了 `0`；
2. 它右边原本所有的 `0` 都变成了 `1`；
3. 更高位的部分保持不变。

于是把原数和 `n - 1` 做按位与：

```text
  1011000
& 1010111
---------
  1010000
```

结果就是：

```text
1011000
↓
1010000
```

恰好少掉了最低位的那个 `1`。

---

## 5. 用更抽象的形式理解

任意一个非零二进制数，都可以从最低位的那个 `1` 处分成：

```text
xxxx1000...000
```

其中：

- `xxxx` 是不受减 1 影响的高位部分；
- 中间这个 `1` 是最低位的 `1`；
- 它右边一定全部是 `0`。

减去 `1` 后：

```text
xxxx0111...111
```

然后按位与：

```text
  xxxx1000...000
& xxxx0111...111
----------------
  xxxx0000...000
```

于是：

```text
n & (n - 1)
```

一定会把最低位的 `1` 清零，而其他更高位保持原样。

这就是整个方法真正的原因。

---

## 6. 为什么这种方法不需要固定循环 32 次

如果采用逐位检查的方法，例如不断：

```c
n & 1
```

然后右移：

```c
n >>= 1;
```

那么需要检查多少次，主要取决于这个整数占了多少位。

但：

```c
n &= n - 1;
```

每次循环都会直接消灭一个 `1`。

因此循环次数取决于：

```text
原数中有多少个 1
```

而不是：

```text
这个整数有多少个二进制位
```

例如某个 32 位整数只有两个 `1`：

```text
10000000000000000000000000000001
```

使用逐位扫描的方法，可能需要检查 32 个位置。

而使用：

```c
n &= n - 1;
```

只需要两次：

```text
第 1 次：清掉一个 1
第 2 次：再清掉一个 1
```

之后：

```text
n == 0
```

循环结束。

所以这种方法真正漂亮的地方，不只是“位运算看起来很巧”，而是它改变了处理方式：

> 普通方法是在检查每一个二进制位；  
> `n & (n - 1)` 则只处理那些真正存在的 `1`。

---

## 7. 三种方法放在一起看

可以把三种做法理解成三个不同层次：

```text
方法一：除 2 取余
       从数学意义上拆出每一个二进制位。

方法二：按位与 + 右移
       直接在整数的二进制表示上逐位扫描。

方法三：n & (n - 1)
       不再逐位扫描，而是每次直接清除一个最低位的 1。
```

对应的函数名可以统一写成：

```c
int count_ones_by_division(unsigned int n);
int count_ones_by_bit_scan(unsigned int n);
int count_ones_by_clearing(unsigned int n);
```

其中第三种的核心只需要记住一句话：

```text
n & (n - 1) 会清除 n 中最低位的那个 1。
```

如果以后又忘了为什么，就不要硬背公式，只需要重新写出：

```text
xxxx1000...000
xxxx0111...111
```

再做一次按位与，整个逻辑自然就能重新推出来。
